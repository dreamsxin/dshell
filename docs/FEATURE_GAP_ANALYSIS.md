# 功能差距分析与实施计划

对比 Netcatty 和 Xshell 8 的功能与界面，分析 dshell 当前差距，列出待实现功能和 UI 优化建议。

## Bitvise SSH Client 对标增量（2026-11-08）

Bitvise 官方产品介绍将 Remote Desktop over SSH 列为集成能力。dshell 的 `v0.1.45` 增加 Windows 端等价工作流：从 Tunnels 面板设置 SSH 主机可达的 RDP host/port，使用 loopback-only 临时本地转发后启动 `mstsc.exe`；临时规则不写入主机资料，SSH session 生命周期负责清理。该功能不实现新的 RDP 协议栈，也不接管 Windows RDP 证书提示。参考：[Bitvise SSH Client](https://bitvise.com/ssh-client)。

`v0.1.46` 补充活动转发连接详情：Tunnels 面板与会话检查器逐连接展示 peer 和目标地址，通道关闭时按唯一连接 ID 移除对应项目。该可观测性适用于本地、远程和 SOCKS5 转发，不持久化客户端地址或连接历史。

Bitvise 9.66 的官方版本记录增加了服务端 Unix socket 转发。`v0.1.47` 对齐该工作流：Local Unix Socket 将本机 TCP 转发到 SSH 服务端的 Unix socket；Remote Unix Socket 将服务端 socket listener 转发到本机 TCP 目标。规则与主机资料一起保存，socket 路径按非空、无控制字符且最多 100 字节校验；旧 JSON 缺少新字段时默认为空。参考：[Bitvise version history](https://bitvise.com/ssh-client-version-history)。

后续 Bitvise 对标继续分批评估 SFTP Drive 映射、CLI 工具和配置兼容性；每项先核对本地原生实现和凭据安全边界，再选可闭环功能，不把产品菜单清单直接复制为承诺。

Bitvise 提供 `sexec` 命令行远程执行客户端。`v0.1.48` 增加原生 `dshell-cli exec`，复用 dshell SSH runtime、认证和严格 known_hosts 检查，支持 agent、私钥和标准输入密码，保留 stdout/stderr 与退出码，并将 CLI 与桌面端一起放入 Windows 安装包。该命令面向非交互自动化，不处理交互式 keyboard-interactive/OTP 提示。

`v0.1.49` 扩展命令行 SFTP 操作：支持 `ls`、`put/get`、`put-dir/get-dir`、`mkdir`、`rm/rmdir`，复用桌面 SFTP worker 的续传、递归条目限制和路径安全检查；目标已存在时需明确选择覆盖或续传。

`v0.1.50` 增加版本化 JSON SFTP batch file，批处理操作在单一已认证 SSH/SFTP 会话中顺序执行。文件限制为 1 MiB、最多 256 项；拒绝未知字段，批处理格式不接受凭据。通配符匹配、变量展开和条件脚本仍未实现。

`v0.1.51` 在 CLI 和 batch file 中增加本地/远端最终路径段通配符传输。父目录保持 literal，匹配 symlink 和 special files 会跳过；通配符结果按名称排序后稳定执行。

`v0.1.52` 为 `dshell-cli exec` 增加显式 `--forward-agent`。默认关闭；开启后只在本次 SSH 会话接受 agent-forward channel，并通过本机 agent 协议流转发签名请求，不复制私钥文件。

`v0.1.53` 为 GUI 主机资料增加可选 agent forwarding；默认关闭，仅对最终目标交互 shell 请求转发，跳板会话不启用。

Bitvise 的 SFTP 命令行工作流提供远端文件属性和规范化路径查询。`v0.1.54` 为 `dshell-cli sftp` 及 JSON batch 增加 `stat` 与 `realpath`，通过 SSH SFTP subsystem 执行，不依赖远端 shell。

`v0.1.55` 扩展 SFTP 文件管理 CLI 和批处理：增加重命名、八进制权限变更、符号链接读取与创建，所有操作复用同一 SFTP subsystem，不调用远端 shell。

Bitvise 的文本传输选项提供跨平台行尾处理。`v0.1.56` 增加显式 `put-text`/`get-text`：上传时将 CR、LF、CRLF 规范化为 LF，下载时统一输出 CRLF；转换按固定块流式执行，其余字节保持不变，普通 put/get 不转换。

`v0.1.57` 为命令行连接增加显式 OpenSSH 用户证书路径；证书认证仍使用私钥签名，私钥口令走既有零化流程，known_hosts 验证保持不变。

`v0.1.58` 扩展到 GUI 保存主机：选择身份文件后，自动发现相邻 `<identity>-cert.pub` 并用于认证；无匹配证书时继续普通公钥认证，发现但无法解析的证书会失败关闭。

Bitvise 支持经 SOCKS 和 HTTP CONNECT 代理建立出站 SSH 连接。`v0.1.59` 为 CLI exec/SFTP 提供无认证 SOCKS5 与 HTTP CONNECT 隧道，代理侧解析目标主机名；SSH 层仍按最终目标地址执行严格 known_hosts 校验。代理认证凭据暂不支持。

`v0.1.60` 将无认证代理扩展到 GUI 主机资料：可选直连、SOCKS5 或 HTTP CONNECT；使用跳板时，代理仅用于本机到首个跳板的 TCP 拨号，后续链路继续由 SSH jump channel 承载。代理认证不支持。

`v0.1.61` 扩展 GUI 与 CLI 出站代理到 SOCKS4 和 SOCKS4A：SOCKS4 在本机解析 IPv4 目标，SOCKS4A 将域名交给代理解析；两者均不支持代理认证。

### 暂缓项实施评估

1. **多窗口支持**：GPUI 原生支持 `cx.open_window`，但 dshell 的 AppView 单窗口架构将全部会话、SSH 事件循环和通道绑定在单一窗口句柄上。拆分会话到独立窗口需要重构会话所有权与事件路由，预计需要一次专门的架构迭代（估计 2-3 天），不适合在既有 244 项测试全部通过的稳定基线末期强行切入。
2. **托盘面板**：GPUI 0.2.2 平台层未暴露托盘 API。需要引入 `tray-icon` crate 或直接调用 Win32 `Shell_NotifyIconW`，并维护独立的消息窗口。该子系统无法在当前隔离环境（无 GUI 自动化验证）下测试，按仓库约束标记为人工验收工作。
**可实施剩余：0 项**（Zmodem/Ymodem、托盘面板、云同步均已交付）。需要架构变更或不可行：多窗口支持（AppView 单窗口架构迭代）；FIDO 直接硬件密钥认证经 Agent 透传覆盖。

## 三、UI 优化建议

### 布局优化

- **地址栏**：工具栏添加地址输入框，Alt+D 聚焦
- **面板停靠**：侧栏/检查器添加自动隐藏
- **标签组**：多组并排，每组显示一个标签
- **工作区预设**：Focus/Standard/Inspector 预设按钮
- **终端侧边栏**：可停靠的 SFTP/转发/日志面板

### 终端体验优化

- **关键词高亮**：内置规则 + 自定义正则
- **保存屏幕**：右键菜单添加"保存可见文本"
- **动态标题**：OSC 0/2 序列更新标签
- **多行粘贴确认**：保护网络设备 CLI
- **终端搜索高亮**：匹配高亮
- **广播模式**：广播模式开关按钮
- **自动重连**：断线自动重连
- **光标行高亮**：WindTerm 风格

### 主机管理优化

- **主机图标**：自动检测发行版图标
- **主机备注**：每个主机可附加备注
- **连接测试**：主机详情中测试连接
- **导入导出**：CSV 导出
- **框选选择**：鼠标框选多个主机

### 视觉与主题优化

- **自定义主题编辑器**：自定义调色板
- **字体连字**：支持 ligatures
- **CJK 字体**：CJK 字体专门支持
- **窗口透明度**：窗口透明切换
- **光标样式**：闪烁、条形宽度

### 暂缓项实施评估

1. **多窗口支持**：GPUI 原生支持 `cx.open_window`，但 dshell 的 AppView 单窗口架构将全部会话、SSH 事件循环和通道绑定在单一窗口句柄上。拆分会话到独立窗口需要重构会话所有权与事件路由，预计需要一次专门的架构迭代（估计 2-3 天），不适合在既有 244 项测试全部通过的稳定基线末期强行切入。
2. **托盘面板**：GPUI 0.2.2 平台层未暴露托盘 API。需要引入 `tray-icon` crate 或直接调用 Win32 `Shell_NotifyIconW`，并维护独立的消息窗口。该子系统无法在当前隔离环境（无 GUI 自动化验证）下测试，按仓库约束标记为人工验收工作。
**可实施剩余：0 项**（Zmodem/Ymodem、托盘面板、云同步均已交付）。需要架构变更或不可行：多窗口支持（AppView 单窗口架构迭代）；FIDO 直接硬件密钥认证经 Agent 透传覆盖。
